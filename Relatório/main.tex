\chapter{Tecnologias e Ferramentas Utilizadas}

\section{Spring Framework e Spring Security}
O backend foi desenvolvido com Spring Boot, utilizando o ecossistema Spring Security para gerir a autenticação e autorização. Esta escolha permitiu uma integração simplificada de mecanismos de segurança avançados, como a proteção contra ataques CSRF (mesmo estando desativada para APIs stateless) e a gestão de contextos de segurança por thread.

\section{JSON Web Tokens (JWT)}
Para a gestão de sessões, optou-se por JWT. Esta tecnologia permite que o servidor não necessite de guardar estado (stateless), o que é ideal para sistemas distribuídos, pois o token enviado pelo cliente contém toda a informação necessária para a sua identificação, permitindo que a API escale horizontalmente sem necessidade de partilhar sessões entre instâncias.

\section{PostgreSQL}
A persistência de dados é assegurada pelo PostgreSQL, um SGBD relacional robusto que garante a integridade dos dados de utilizadores, produtos e vendas através de transações ACID.

\section{React e Vite}
O frontend foi construído utilizando React, uma biblioteca JavaScript para a criação de interfaces de utilizador dinâmicas. O ambiente de desenvolvimento Vite foi escolhido pela sua velocidade e suporte nativo a módulos ES.
\chapter{Implementação}

\section{Arquitetura de Segurança}
A segurança da aplicação foi desenhada para proteger os dados dos utilizadores e garantir que apenas utilizadores autorizados acedem a recursos sensíveis.

\subsection{Autenticação e Hashing de Passwords}
O processo de autenticação baseia-se em dois fluxos principais: registo e login. No registo, os dados são validados e a password é cifrada utilizando o algoritmo \textbf{BCrypt} antes de ser persistida na base de dados. O BCrypt adiciona um "salt" aleatório a cada password, protegendo o sistema contra ataques de força bruta e dicionário.

\subsection{Gestão de Sessões com JWT}
Ao efetuar login com sucesso, o servidor gera um token JWT assinado digitalmente com uma chave secreta configurada em variáveis de ambiente. Este token tem uma validade de 24 horas e deve ser enviado pelo frontend em todos os pedidos subsequentes através do cabeçalho \textit{Authorization}.

\subsection{Middleware de Segurança (Filtros)}
Implementou-se o \texttt{AuthTokenFilter}, que estende \texttt{OncePerRequestFilter}. Este filtro interseta cada pedido HTTP, valida o token JWT e, caso seja válido, carrega os detalhes do utilizador para o contexto de segurança do Spring, permitindo que o controlador saiba quem é o utilizador ativo.

\begin{lstlisting}[caption={Configuração do SecurityFilterChain no Backend}]
@Bean
public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
    http.csrf(csrf -> csrf.disable())
        .sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
        .authorizeHttpRequests(auth -> 
            auth.requestMatchers("/api/auth/**").permitAll()
                .requestMatchers("/api/produtos/public/**").permitAll()
                .anyRequest().authenticated()
        );
    return http.build();
}
\end{lstlisting}

\section{Integração Frontend-Backend}
A comunicação entre as duas camadas é feita através de serviços assíncronos no frontend. Criou-se um \texttt{AuthService} em JavaScript que utiliza a API \textit{fetch} para consumir os endpoints REST do backend. O token recebido é armazenado no \texttt{localStorage} para persistência da sessão no browser.

\chapter{Conclusões e Trabalho Futuro}

\section{Conclusão}
O desenvolvimento deste projeto permitiu consolidar os conhecimentos sobre a criação de aplicações web distribuídas utilizando a framework Spring. A implementação de um sistema de segurança baseado em JWT e a integração com uma base de dados relacional demonstraram a importância da robustez e escalabilidade em sistemas modernos.

\section{Trabalho Futuro}
Para versões futuras deste sistema, poderiam ser implementadas as seguintes melhorias:
\begin{itemize}
    \item \textbf{Sistema de Pagamento:} Integração com gateways de pagamento reais (ex: Stripe ou PayPal).
    \item \textbf{Notificações:} Implementar um sistema de notificações por email para confirmação de encomendas.
    \item \textbf{App Móvel:} Desenvolver uma aplicação mobile nativa que consuma a mesma API REST.
\end{itemize}
